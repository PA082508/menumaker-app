## ⚠️ Оговорка о признаке

«Не упомянута в коде» **не значит «не используется»**: часть таблиц пишется **из базы**, функциями
`SECURITY DEFINER`, и в дереве приложения их имён нет по построению.

**Проверенный пример:** `child_person_events` заполняется `record_child_person` и читается видом
`v_person_link_questions`. Она в списке ниже **отсутствует по этой причине** — исключена руками
после проверки, а не пропущена.

Признак остаётся полезным: он находит **схему без проводки**, но каждую строку надо посмотреть.

### ⚠️ `safepass_ratio_events` — НЕ дешёвая. Замер по входам, 29.07

Я написал «считается из того, что уже есть». **Владелец спросил, откуда берётся присутствие, — и
допущение развалилось.** Построчно:

| Вход | Живой? | Замер |
|---|---|---|
| `children_present` **в момент времени** | ❌ **нет источника** | `safepass_sessions` = **0**; таблицы посещаемости нет вовсе (есть `attendance_forecasts` — прогноз — и `attendance_patterns`). Живой журнал посещаемости **не построен**: учителя видят «copy these times» |
| `teachers_present` | ❌ **нет** | `staff_time_log` = 0 · `safepass_duty_sessions` = 0 |
| `youngest_age_months` | ✅ есть | 300 активных детей с датой рождения, считает `v_child_age_profile` |
| `capacity_ohio` / `capacity_internal` | ✅ есть | заполнены у **34 комнат из 34** |

**Два входа из четырёх, и недостающие — ровно те, ради которых таблица заведена.** Она уходит в
очередь **ЗА журналом посещаемости**, и записано это здесь, чтобы её больше не считали дешёвой.

⚠️ **Честная половинка, которая всё-таки есть:** `meal_count_marks` — **5863 отметки**, то есть
присутствие ребёнка **в моменты приёмов пищи** зафиксировано фактически. Соотношение **в четыре
известных момента дня** посчитать можно, «в 10:15» — нельзя. Но вторая половина (**сколько
педагогов в комнате**) отсутствует и там, поэтому вывод не меняется.
