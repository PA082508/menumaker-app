# Схема опережает пути: карта дешёвых выигрышей

**Это карта дешёвых выигрышей, а не список долгов.** Повод (владелец, 29.07): три пустые
неподключённые таблицы подряд оказались ровно тем, что было нужно —

- `documents` — пуста, но манифест Doc Hub её уже читает, и заход 2 оказался **проводкой, а не
  схемой**;
- `milk_substitutions` — пуста при живых заменителях молока;
- `medication_log` — существует, 0 строк, **в коде не упомянута ни разу**, и именно она делает
  01217 первым среди трёх тёмных форм: потребитель построен и ждёт основания.

**Проектировали верно, недостаёт проводки.** Замер read-only, 29.07: 59 пустых таблиц в
`menumaker`, из них **27 не упомянуты в дереве** (`src`, `public`, `supabase`).

---

## ⚠️ Оговорка о признаке

«Не упомянута в коде» **не значит «не используется»**: часть таблиц пишется **из базы**, функциями
`SECURITY DEFINER`, и в дереве приложения их имён нет по построению.

**Проверенный пример:** `child_person_events` заполняется `record_child_person` и читается видом
`v_person_link_questions`. Она в списке ниже **отсутствует по этой причине** — исключена руками
после проверки, а не пропущена.

Признак остаётся полезным: он находит **схему без проводки**, но каждую строку надо посмотреть.

## SafePass — построенный, но не включённый слой (6)

| Таблица | Судя по колонкам, держит |
|---|---|
| `safepass_duty_assignments` | кто из педагогов дежурит у двери и в какие часы (`teacher_id, duty_date, duty_start, duty_end, mode`) |
| `safepass_duty_sessions` | смена дежурства целиком: начало, конец, сколько детей прошло (`duty_type, started_at, ended_at, children_count, status`) |
| `safepass_ratio_events` | **соблюдение соотношения взрослые/дети по Огайо в момент времени** — `children_present, teachers_present, youngest_age_months, effective_ratio, capacity_ohio, alert_level`. Регуляторная величина, сегодня не считается вовсе |
| `safepass_room_transfers` | перевод ребёнка между комнатами **с подтверждением обоих педагогов** (`from_teacher_confirmed_at, to_teacher_confirmed_at`) |
| `safepass_substitutions` | подмена педагога в комнате, тоже с двойным подтверждением |
| `safepass_key_tags` | брелок/метка для быстрого опознания у двери (`tag_id, person_type, child_ids`) |
| `safepass_late_escalations` | опоздание за ребёнком: на сколько минут, кому звонили, чем кончилось |

**Дешевле всего** здесь `safepass_ratio_events`: величина считается из того, что уже есть
(присутствие детей + смены персонала), а даёт регуляторный показатель, который сегодня никто не
измеряет.

## Персонал — почти целый HR-контур (10)

| Таблица | Держит |
|---|---|
| `staff_schedule_plan` | **плановая** сетка смен на неделю (в отличие от живой `staff_schedules`) |
| `staff_time_log`* | отметки прихода/ухода |

| `staff_overtime_auth` | **разрешение на переработку до факта** (`max_ot_hours, approved_by`) |

| `staff_onboarding` + `onboarding_steps` | ввод в должность по шагам |
| `staff_training_requirements` + `training_resources` | **что обязателен пройти по должности** (`hours_required, expires_months, regulatory_ref`) и где это пройти |

**Дешевле всего** — пара `staff_training_requirements` + `training_resources`: у нас уже есть
`staff_training_records` (тоже пуста, но подключена — карточка сотрудника пишет в неё), и
требования превращают россыпь записей в **«сколько часов не хватает до нормы»**.

## Как этим пользоваться

**Не как списком задач.** Правило: **когда работа подходит к области, сперва заглянуть сюда** —
велика вероятность, что таблица уже есть, названа верно и ждёт проводки. Сегодня это сэкономило
заход 2 (схема была готова) и дало основание приоритету 01217.

**Read-only.** Ни одна строка отсюда не трогается без отдельного слова.
