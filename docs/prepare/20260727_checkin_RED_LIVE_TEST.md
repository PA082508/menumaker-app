# Живой чеклист: чек-ин / чек-аут учителей

## Поправка, из-за которой чеклист переписан

Прежний шаг 7 предлагал **«сменить комнату в селекторе»**. Селектора на этом устройстве **нет и
быть не должно**: пад зарегистрирован на Red и подписан «locked to this room». Флоатер, вошедший
по PIN на этом паде, попадает **в Red** — и это **правильно**, а не дефект: канон «программа
отражает действительность» — человек работает там, где стоит планшет.

**Где тогда живёт выбор комнаты флоатером.** Параметр `p_classroom` у
`safepass_staff_check_in` остаётся, но он **не для запертого классного пада**. Он для
**незапертых поверхностей**: телефона по BYOD (в т.ч. водительского в ходе 2-Т) и общего
центрового пада, если такой появится. Правило одной строкой: **на устройстве, привязанном к
комнате, выбора комнаты не существует; выбор появляется только там, где у устройства своей
комнаты нет.**

## Как проверять шаги 3, 6 и 10 по базе

```sql
select to_char(e.event_at at time zone 'America/New_York','HH24:MI:SS') as t_ny,
       s.first_name||' '||s.last_name as who, e.event_type, c.name as room
  from menumaker.staff_time_events e
  join menumaker.staff s on s.id = e.staff_id
  left join menumaker.classrooms c on c.id = e.classroom_id
 where e.event_at >= menumaker.center_local_day_start('4aed7d5a-00d0-4a4c-ac99-311046ad2027')
 order by e.event_at;
```

События обязаны идти **парами** `check_in` → `check_out` на человека. Лишняя строка после
повторного тапа = дефект сервера; **отсутствие лишней строки при отсутствии сообщения на
экране = дефект экрана** (ровно это и случилось 27.07).
