# Сужение строк `staff` / `staff_schedules` — предполёт и сверка

**Готово 28.07 вечером. Применять утром 29.07, при свидетелях, не в ночь.**
Файл миграции: `20260729a_staff_row_narrowing.sql`

## Предполёт — что замерено ДО применения

| Замер | Ответ | Почему это важно |
|---|---|---|
| Политика на `staff` сейчас | одна, `auth_manage`, `using: true` | любой вошедший видит все 105 строк трёх центров |
| Политика на `staff_schedules` | та же | расписания так же общие |
| Покрывает ли `auth_manage` запись | **да**, `with check: true` | это был не вопрос видимости — с кухни переписывался чужой `pin_hash` |
| `pin_hash` | закрыт колонкой 28.07 (`20260728aa`) | самое опасное закрыто отдельно и от этой миграции не зависит |
| Кто останется без центра | **admin 0 · office_manager 0 · accountant 0** | чисто центровая формула ослепила бы всех троих **молча** |
| Сколько центров у кухни | 1 | после сужения планшет увидит свой центр вместо трёх |
| Читатели `staff` в коде | 6 экранов, все с явным списком колонок | `select('*')` убран 28.07, иначе колонковое закрытие обнулило бы карточку |

## Что проверяем ПОСЛЕ применения — живой сверкой

Порядок важен: сперва то, что могло сломаться, потом то, что должно было закрыться.

1. **Директор видит своих.** Войти директором → *Staff* → список не пуст, в нём только сотрудники его центра, чужих нет.
2. **Офис-менеджер видит всех.** Войти Татьяной → *Staff* → видны сотрудники всех трёх центров. **Пустой список здесь = провал**, откатываем.
3. **Зарплатные экраны живы.** Карточка сотрудника → вкладка *Work* → ставка, оклад, тип оплаты, переработка на месте; *Daily Time Log* считает часы.
4. **Расписание живо.** В карточке — недельная сетка смен читается и сохраняется.
5. **Кухонный аккаунт не видит лишнего.** Войти кухней → там, где список персонала доступен, — только свой центр. Ни одного сотрудника чужого центра.
6. **Вход по PIN работает.** SafePass: приём/выдача ребёнка по PIN проходит (проверяет `security definer`, колонка закрыта — путь не должен пострадать).
7. **Послеполёт зелёный.** `docs/maintenance/postflight.sql` целиком: S-1 и S-2 обязаны быть ✅.

## Откат, если что-то из 1–6 красное

Одной строкой, forward-only не нарушает — политика не запись:

```sql
drop policy if exists staff_scope on menumaker.staff;
drop policy if exists staff_sched_scope on menumaker.staff_schedules;
create policy auth_manage on menumaker.staff for all to authenticated using (true) with check (true);
create policy auth_manage on menumaker.staff_schedules for all to authenticated using (true) with check (true);
```
