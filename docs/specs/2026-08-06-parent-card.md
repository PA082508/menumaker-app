# Карточка родителя — спека (06.08.2026)

## Канон, первой строкой

**ОДНА ЗАПИСЬ — ДВА ВХОДА.** Одно и то же окно человека открывается и через родителя, и через
ребёнка. Никаких копирующих таблиц и никакой «родительской версии» тех же данных: клик
ребёнок → родитель и клик родитель → ребёнок симметричны и приводят в одно место.

Практическое следствие: у карточки родителя **один адрес** (`/parents/:guardianId`), и переход из
карточки ребёнка ведёт по нему же. Список детей в карточке родителя ведёт в карточку ребёнка тем
же способом, каким карточка ребёнка ведёт в карточку родителя.

---

## 1. Что уже есть (замер, а не предположение)

| слой | сегодня |
|---|---|
| носитель | `guardian` + связка `child_guardian` (`relationship`, `role`, `can_pickup`, `is_emergency_contact`, `ordinal`) |
| вход через ребёнка | вкладка **Family** в карточке ребёнка: читает `child_guardian … guardian:guardian_id(*)` по `roster.child_id` |
| вход через родителя | **нет**: `ParentsPage` показывает грид карточек `FamilyCard` с правкой контактов на месте, но у родителя нет своего окна |
| ✓Pickup | `child_guardian.can_pickup` (импорт), плюс отдельный носитель прав у двери `safepass_trusted_persons` |
| SafePass-статус | `safepass_trusted_persons`: `registered_at`, `phone_verified`, `photo_url` |
| income-бейдж | `income_determination_status()` — content-free, по `roster.id` |

⚠️ **Ловушка ключей, которую спека обязана держать:** `child_guardian.child_id` → `menumaker.child.id`
(через `roster.child_id`), а `safepass_trusted_persons.child_id` → **`roster.id`**. Это РАЗНЫЕ ключи,
и на них уже дважды ловились (скрытый раздел Step-3, мёртвая медкарта). Карточка родителя сшивает
оба, поэтому оба перехода пишутся явно и покрываются пробой.

## 2. Список вместо грида

`ParentsPage` сегодня — грид карточек шириной 300px. Становится **компактным списком**:

```
🔎 поиск сверху (имя родителя, имя ребёнка, телефон)

[фото 48]  Deidra Booker              (216) 555-0134      2 children   →
[фото 48]  Bryant Jackson             (216) 555-0198      2 children   →
[фото 48]  Lindsey Kendzierski        (440) 555-0110      1 child      →
```

- аватар — `AVATAR.row` из общего ряда (никаких новых чисел);
- **income-бейджи уходят из списка в карточку** — в списке они шум и лишний повод для взгляда
  соседа; содержимое остаётся content-free там, где было;
- **класс-вид (sheet) остаётся вторым взглядом ТОЙ ЖЕ страницы** — переключатель
  `🗂 Families | 👪 Parents sheet` не трогается.

## 3. Карточка родителя — паттерн карточки сотрудника

`/parents/:guardianId`, вкладки как у staff:

**Profile** — контакты с правкой (имя, e-mail, mobile/phone_1/phone_2, адрес). Правка уже живёт в
`FamilyCard.save()` с проверкой «0 строк = не записалось» — переносится дословно, а не пишется
заново.

**Children** — дети этого взрослого: имя · комната · F/R/P · **income-бейдж** (тот самый,
переехавший из списка) · тип связи (`relationship`/`role`) · **✓Pickup** · переход в карточку
ребёнка. Симметрия входов: отсюда — к ребёнку, из вкладки Family ребёнка — сюда.

**SafePass** — состояние двери по этому человеку: телефон, `✓ registered` / `✓ signed-in`, фото
(то самое, снятое при Register), кто и когда зарегистрировал. Только показ: заводит и отзывает
доступ экран `/safepass/issue`, второй двери к записи не заводим.

**Documents** — ⏸ **ОТЛОЖЕНО из v1** (слово владельца 06.08): подачи, где этот взрослый подписант, добавляются отдельным заходом по слову.

## 4. Чего спека НЕ делает

- не заводит вторую таблицу родителей и не копирует поля ребёнка;
- не даёт править `can_pickup` из карточки, пока право забирать не сведено в один носитель
  (сейчас их два: `child_guardian.can_pickup` и `safepass_trusted_persons`) — это отдельный заход
  [[pickup-authorization]], и до него карточка **показывает оба и говорит, если они расходятся**;
- не показывает содержание income-определения — только «на файле», как сегодня;
- не трогает печать.

## 5. Пробы

1. вход через родителя и вход через ребёнка приводят в **одно** окно (один адрес);
2. ключи: у ребёнка с `roster.child_id = null` карточка родителя не падает и говорит, почему пусто;
3. правка контакта, отбитая RLS, показывает отказ (0 строк ≠ «Saved ✓»);
4. income-бейдж в списке отсутствует, в карточке присутствует;
5. расхождение `can_pickup` и `safepass_trusted_persons` показано словами, а не молча одной из сторон;
6. регресс: класс-вид sheet и грид Families работают как раньше.
