# Транспортное плечо (н)

Этот файл — **карта**, а не задание на стройку. Он существует, чтобы решения, принятые
26–27.07, не изобретались заново. Всё, что ниже, **ратифицировано словом Николая**; всё, что
измерено, помечено как измеренное.

## 1. Канон опеки школьника — границы У ШКОЛЫ

**PM-in = тап водителя при посадке в автобус у школы. AM-out = тап при высадке у школы.**
Передача автобус→класс в саду — **внутренняя**, в табель **не пишется**.

Внутренний след этой передачи **НЕ строим** (решение 27.07): строка без бумажного аналога
развела бы журнал с печатью.

## 2. Ось модели — РЕЙС (решение 27.07, развилка «водитель vs школа» закрыта)

**run = водитель + автобус + дата + am/pm.** Водитель — **подписант**: атрибуция на каждом тапе.

**ШКОЛА = свойство РЕБЁНКА/ТАПА, НЕ рейса.** Один рейс обслуживает несколько школ, тапы у
каждой со своим временем.

**Превышение вместимости = просто ДВА РЕЙСА** (два водителя параллельно ИЛИ один двумя ходками).
⚠️ Печатная единица — **НЕ «лист на рейс»**: образец недельный, см. §5.5.

### 2.3. REDLINE 27.07 — вместимость есть ЖЁСТКАЯ НОРМА (заменяет «мягкое предупреждение»)

**Слово Николая 27.07. Прежняя формулировка «soft warning по образцу ratio, не гейт» ОТМЕНЕНА.**
`vehicle_capacity` — значение **на машину** (у Wickliffe-автобуса = **14**), платформа его не
хардкодит: у клиентов свои машины и свои числа.

1. **Гейт при комплектовании рейса.** Ребёнок сверх вместимости **НЕ добавляется**: отказ +
   предложение **создать второй рейс**. Это запрет планирования сверх нормы, а не предупреждение —
   прямое следствие Правила №1.
2. **Форс-мажор фактической посадки.** Если в автобус физически сел неприписанный ребёнок —
   запись **НЕ блокируется** и **не молчит**: она проходит как **помеченное исключение** в журнал
   директору, по канону «исключения помечены, не спрятаны».
3. Сам `alter` из §2.2 **остаётся как написан** — меняется только семантика поля: **hard gate**,
   не soft warning.

### 2.2. Минимальная forward-only правка (prepare — НЕ применена, ждёт go)

```sql
-- школа = свойство РЕБЁНКА/тапа, не рейса
alter table menumaker.safepass_transport_children
  add column if not exists school_name text;
-- вместимость машины = мягкое предупреждение, не гейт
```

`runs.school_name` **не трогаем и не удаляем** — остаётся ярлыком рейса для одношкольных
маршрутов и старых строк. Чтение: школа берётся с ребёнка, при пустом значении — падает на
ярлык рейса.

## 3. Календари — запись от них НЕ зависит

Времена = **фактические тапы**. Разные школы дают разные факты; система расписаний не знает.
Справочник школ (времена, каникулы, атрибут школьника) — **опция** для маршрут-листа и будущих
алертов, **позже отдельным словом**.

## 4. Driver-UI (MVP)

Экран рейса на устройстве водителя: **BYOD-телефон**; бейдж-вход из (л) — опция. Список детей
маршрута, тап посадки/высадки, **двухшаговость** от случайного тапа. Календаря нет.

### 4.1. Колонка SCHOOL и группировка по школам (решение 27.07)

В списке рейса **на экране водителя** — колонка **SCHOOL** напротив каждого ребёнка (из
`safepass_transport_children.school_name`, §2.2) и **сортировка/группировка по школе**: список
читается как маршрут — у каждой школы её дети идут верхней группой, в порядке следования.

**Печатный лист рейса — БЕЗ этой колонки**, строго по образцу `Bus-Wickliffe`: канон
«**печать = образец**». Экран помогает больше, бумага копирует бланк 1:1. Подтверждено чтением
образца: колонки SCHOOL на бланке нет.

Шаг **«Attach paper sheet»** — см. §5.3.

## 5. Печать и хранение листов (решение 27.07)

### 5.1. Заполненный лист — печатает ДИРЕКТОР/ОФИС

Кнопка **Print** у рейса в транспортном журнале. Десктоп **и** карман (з), права —
`my_center_ids() OR menumaker.is_org_owner(org_id)` (тот же предикат, что у остальных
staff-поверхностей SafePass).

**Лист воспроизводим за ЛЮБОЙ прошлый день: первичная запись — система.** **Водитель НЕ
печатает.**

### 5.2. Пустой бланк — карточка Document Hub

Пустой **Routine Trip Checklist** — карточка в Doc Hub, печатает **любой staff**: запас в
автобус для ручного fallback. Блокер снят: образец приобщён —
[`Attendance_Ridge_-_Bus-Wickliffe1.pdf`](../samples/attendance/Attendance_Ridge_-_Bus-Wickliffe1.pdf).

### 5.3. Ручной fallback

Заполненный от руки лист водитель **фотографирует** → **`transport_runs.checklist_photo`**
(колонка **уже существует** — использовать по назначению, не заводить вторую). Шаг **«Attach
paper sheet»** в driver-UI. Фото хранится **по фото-дисциплине**: приватный bucket, путь а не
URL, короткий signed URL для персонала, никакого распознавания (см. platform-standards).

### 5.4. Бумага

Хранение — **папка центра, как классные листы**. Канон **parallel-run** распространяется:
**бумага остаётся официальной записью до решения центра.**

## 5.6. REDLINE 27.07 (исправлен тем же днём) — строки листа = НЕДЕЛЬНЫЙ СПИСОК автобуса

**Слово Николая 27.07, коррекция: два числа были смешаны, «строк = ровно `vehicle_capacity`»
ОТМЕНЕНО.** Правильное разделение:

| Число | Что означает | Чем держится |
|---|---|---|
| **`vehicle_capacity`** (Wickliffe = 14) | **одновременная ЗАГРУЗКА рейса** — детей в одной ходке / одной колонке **≤ вместимости** | **экран**: жёсткий гейт комплектования §2.3 **остаётся как записан**, плюс помеченные исключения при форс-мажоре. **Бумага нормы не несёт** |
| **число строк листа** | **недельный СПИСОК автобуса**: приписанных может быть 20 при вместимости 14 — не каждый ездит каждый день | **динамика по числу детей списка**, ровно как у SA2 (29 строк), с добивкой пустыми строками как в образце |

**Пустой бланк из Doc Hub — тоже по списку** (с запасом строк), **не по машине**.

**Расхождение снято.** «≈22 строки против 14 мест» на `Bus-Wickliffe1.pdf` — не дефект образца:
22 строки это список автобуса, а 14 — вместимость одной ходки. **Образец был прав, и канон
«образец побеждает спеку» восстановлен БЕЗ исключения.**

## 5.5. ⚠️ Образец прочитан: лист НЕДЕЛЬНЫЙ, не «один на рейс»

Чтение [`Attendance_Ridge_-_Bus-Wickliffe1.pdf`](../samples/attendance/Attendance_Ridge_-_Bus-Wickliffe1.pdf)
(26.07) показало ту же недельную ось, что у классных листов: Mon–Fri × am/pm, служебные строки
`Departure / Arrival Time` и `Driver's name`, метка `OnBus/Off`. Печатная единица — **лист на
АВТОБУС за неделю**, рейс = **одна колонка**; два параллельных рейса = **два листа** (по листу на
автобус). Записанное ранее «лист печати — один на рейс» с образцом расходится, а по канону
«образец побеждает спеку» выигрывает образец. **Нерешённый случай:** один водитель и один автобус
двумя ходками в одну половину дня — обе ходки претендуют на одну колонку. Ждёт слова.

## 6.2. (п) FIELD TRIPS — экскурсии

**Слово Николая 27.07. Только запись; стройка — после повторного смоука.**

### Тот же рейс, тот же рельс

Экскурсия — это **рейс** с `run_type='field_trip'` (значение по схеме `safepass_transport_runs`):
водитель + автобус + дата, тапы посадки/высадки в `safepass_transport_children`, **гейт
вместимости §2.3 работает как есть**. Ничего нового не строится — переиспользуется весь рельс
2-Т: driver-UI, RPC, атрибуция водителя, `Attach paper sheet`.

### ⚠️ ОПЕКА НЕ ПЕРЕДАЁТСЯ — главное отличие от школьного плеча

У школьного рейса граница опеки проходит **у школы** (§1): там ребёнок переходит из рук в руки,
и это событие табеля. **У экскурсии передачи нет вообще**: дети под опекой центра **всю
поездку**, едут с учителями и возвращаются с ними.

Следствия, обязательные к соблюдению:

- **Field trip НЕ пишет OUT/IN в классный журнал.** Ребёнок весь день числится присутствующим в
  центре — потому что он и есть в присутствии центра.
- **`v_attendance_day` и печать листов ИСКЛЮЧАЮТ тапы рейсов с `run_type='field_trip'`.** Это
  фильтр, который надо написать явно: без него экскурсия выглядела бы как уход и приход ребёнка.
- Тапы экскурсии = **внутренний транспортный учёт**: кто в автобусе, кто вышел. AM/PM-разметка
  §0.6 спеки посещаемости к ним **не применяется**.

### Гейт Правила №1 — «no child left on bus»

**`Run completed` блокируется, пока хоть один ребёнок в статусе `OnBus`.** Рейс нельзя закрыть с
ребёнком в салоне. На экране водителя — постоянная сверка **«село N · вышло M»**, и при попытке
закрыть с `N > M` отказ называет **имена** оставшихся, а не число.

**Правило универсальное, не экскурсионное.** Школьный рейс закрывать с ребёнком на борту нельзя
ровно так же — экскурсия лишь сделала это очевидным. Гейт ставится в
`safepass_driver_complete_run` для **всех** `run_type`, а не под условием field trip.

### Гейт «no child left on bus» покрывает field_trip БЕЗ ИСКЛЮЧЕНИЙ — проверено кодом

`safepass_driver_complete_run` (ядро, применена 27.07) отбирает детей **только по
`status='boarded'` и не смотрит на `run_type` вообще**. Значит экскурсия закрывается по тому же
правилу, что школьный рейс: пока кто-то на борту — `children_still_aboard` с именами. Ветки
«кроме экскурсий» в функции нет и заводить её нельзя.

Проба 27.07 (в откате) прошла на `morning_to_school`; на `field_trip` путь тот же код без
условий — отдельная проба будет частью смоука экскурсии.

### Сопровождающие учителя — вердикт уточнён 27.07: ХВОСТОМ, не в MVP

Ранее я писал «атрибуцию писать сейчас». **Уточняю, и вот чем:** на школьном рейсе взрослый один
и он уже записан — `driver_staff_id` на рейсе и `checked_by = staff.id` на каждом тапе, вопрос
«кто был с детьми» отвечается. **Сопровождающие появляются только на экскурсии**, а экскурсия
сама по себе — хвост 2-Т. Значит `safepass_transport_staff` строится **вместе с экскурсионной
спецификой**, не раньше: до первой реальной экскурсии таблица стояла бы пустой, а Правило №1 на
школьных рейсах уже закрыто водителем.

**Расчёт ratio в поездке — Planned** (тот же непостроенный модуль, что и nap-исключение).

**Атрибуцию писать СЕЙЧАС для водителя — сделано** (`driver_staff_id`, `completed_by`). Сегодня на рейсе есть только водитель
(`driver_name`, `driver_phone`); кто из персонала поехал с детьми — **не записано нигде**, а это
вопрос Правила №1 («кто был с детьми, когда автобус уехал»), на который задним числом обязан
быть ответ. Цена — одна маленькая таблица:

```sql
-- prepare, НЕ применено
create table if not exists menumaker.safepass_transport_staff (
  id         uuid primary key default gen_random_uuid(),
  run_id     uuid not null references menumaker.safepass_transport_runs(id),
  staff_id   uuid not null references menumaker.staff(id),
  role       text,                       -- 'chaperone' | 'lead' | 'driver'
  joined_at  timestamptz not null default now()
);
```

**Расчёт ratio в поездке — Planned:** он упирается в тот же непостроенный модуль, что и
nap-исключение (`compliance-map.md`, 🟡 Partial). Записывать, кто поехал, и **считать**, хватило
ли взрослых, — две разные задачи; первая дешёвая и нужна сейчас, вторая ждёт модуля.

### Permission slips — PLANNED, место в v4 «право забирать»

Разрешения родителей на экскурсию — **документ-рельс v4**, тот же, что несёт «право забирать»
(`child_release_authorization`): форма → подпись родителя → хранение → **проверка перед
посадкой**. Логика одна и та же — родитель заранее разрешает конкретное действие с ребёнком, а
экран у двери (здесь — у автобуса) это разрешение проверяет. **Не строим**, записано строкой,
чтобы не изобреталось рядом со «правом забирать» вторым механизмом.

### Место в очереди

**Хвост 2-Т**, как вы и предположили: рельс тот же, добавляются `run_type='field_trip'`, фильтр
экскурсий в журнале и таблица сопровождающих. **Исключение — гейт «no child left on bus»: он
идёт в ЯДРО 2-Т**, вместе с `safepass_driver_complete_run`, потому что нужен школьным рейсам с
первого дня.

## 6.3. Мини-Devices в составе 2-Т — цена (вопрос Николая 27.07)

**Регистрация водительского телефона на смоук:** сегодня — **SQL-ом**, экрана нет. И существующая
`safepass_register_device(p_org, p_center, p_classroom, p_label)` **не знает `device_kind`** и
требует комнату, поэтому driver-устройство ею не завести: нужен либо параметр, либо прямой
INSERT с заранее посчитанным `token_hash`.

**Цена мини-экрана Settings → SafePass → Devices (список + Register-ссылка + Revoke):**

| Кусок | Есть | Цена |
|---|---|---|
| Минт токена | `safepass_register_device` — **есть**, но без `device_kind` и с обязательной комнатой | **МАЛО**: `create or replace` с двумя параметрами (`p_kind default 'classroom'`, комната nullable) |
| Список устройств | RPC **НЕТ** | **МАЛО**: одна `safepass_devices_for_center()` с предикатом `my_center_ids() OR is_org_owner()` |
| Revoke | RPC **НЕТ** (revoke сегодня только руками) | **МАЛО**: одна функция, ставит `revoked_at`, `is_active=false` |
| Доставка токена на телефон | маршрут **`/t/:token` УЖЕ РАБОТАЕТ** (путь, не query — Mail/Notes не режут) | **0** |
| Экран | — | **МАЛО**: таблица + кнопка + модалка со ссылкой/QR (`qrcode.react` уже стоит) |
| `last_seen_at` | колонки **нет** | **исключить из мини-версии**, оставить в ход 3 |

**Итого: одна миграция на три функции + один экран ≈ полдня.** Дёшево именно потому, что рельс
доставки токена уже построен и доказан. **Рекомендую взять хвостом 2-Т** — иначе каждого водителя
директор подключает через меня, а это ровно та зависимость, которую мы всюду убираем.
**Полная версия** (last-seen, re-label, статусы, история) остаётся ходом 3.
